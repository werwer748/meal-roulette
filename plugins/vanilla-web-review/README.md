# vanilla-web-review

빌드 도구 없는 바닐라 웹 코드를 위한 코드 품질 키트. 단일 HTML + 인라인 JS/CSS + Canvas +
`localStorage` 조합처럼 **프레임워크가 막아주던 것이 없는** 코드를 대상으로 한다.

React가 막아주던 XSS, 번들러가 잡아주던 문법 오류, 상태 관리 라이브러리가 강제하던 단방향 흐름이
전부 사람 몫인 환경에서 그 빈자리를 메우는 게 목적이다.

## 구성

| 종류 | 이름 | 하는 일 |
|---|---|---|
| 스킬 | `web-review` | 8항목 체크리스트와 🔴/🟡/🟢 보고 형식. 리뷰의 *절차*를 정의한다 |
| 서브에이전트 | `web-reviewer` | 위 스킬을 호출해 실제 리뷰를 수행하고 보고서 하나를 돌려준다 |
| 훅 | `PreToolUse(Bash)` | Claude가 `git commit` 을 실행하려 하면 검사 스크립트를 먼저 돌리고, 실패하면 커밋을 막는다 |

셋은 역할이 겹치지 않는다. 스킬은 기준, 에이전트는 실행, 훅은 강제다.

## 쓰는 법

리뷰는 그냥 말로 부르면 된다.

```
index.html 리뷰해줘
```

`web-reviewer` 에이전트가 붙어서 검사 스크립트를 돌리고, 체크리스트를 훑고, 심각도별 보고서를 낸다.
**코드는 고치지 않는다** — Edit 권한이 없는 것은 실수가 아니라 의도다. 무엇을 고칠지는 사람이 정한다.

## 체크리스트

기계가 잡을 수 있는 것을 먼저 기계에 맡긴 다음, 위에서부터 훑는다. 위쪽이 더 치명적이다.

1. **저장소** — `try/catch`, `JSON.parse` 결과 검증, 저장 실패 통지, 스키마 버전
2. **XSS와 DOM 주입** — `innerHTML`에 들어가는 값, `eval`/`document.write`, 속성 주입
3. **이벤트와 수명주기** — 중복 바인딩, 재렌더 시 포커스 유실, `transitionend` 미도착, 옵저버 해제
4. **애니메이션과 Canvas** — 연출 중 상태 변경, `devicePixelRatio`, 누적 transform, `prefers-reduced-motion`
5. **무작위성** — 모듈로 편향, 결과를 먼저 정하는가 연출에서 읽는가, "공정하다"는 주장의 실제 확률
6. **경계값** — 0개 / 1개 / 아주 많을 때, 필터 전체 해제, 공백 입력, 중복, 폴백의 무한 루프
7. **접근성** — `aria-live`, 키보드만으로 완주, 아이콘 버튼 이름, 색에만 의존하지 않기
8. **반응형과 단일 파일 제약** — 390px 가로 스크롤, 외부 CDN 참조, `alert`/`confirm`/`prompt`

**🔴는 재현 시나리오를 못 쓰면 🔴가 아니다.** "XSS 위험이 있습니다"가 아니라
"메뉴 이름에 `<img src=x onerror=...>`를 넣고 새로고침하면 실행된다"라고 쓴다.

## 커밋 훅

`git commit` 을 감지하면 프로젝트의 검사 스크립트를 돌린다. 찾는 순서:

1. 환경 변수 `VANILLA_WEB_CHECK` 에 지정한 경로
2. `<프로젝트>/scripts/check.sh`
3. `<프로젝트>/check.sh`

셋 다 없으면 커밋을 막을 근거가 없으므로 조용히 통과시킨다. 검사 스크립트가 없는 프로젝트에
이 플러그인을 깔아 두어도 아무 일도 일어나지 않는다.

실패하면 `exit 2` 로 커밋을 막고 실패 출력 전체를 Claude에게 돌려준다. 커밋이 아닌 Bash 호출은
payload 문자열만 보고 즉시 빠지므로 (측정값 기준 10ms대) 상시 부담이 거의 없다.

### 이건 git 훅이 아니다

Claude Code 훅이라 **사람이 터미널에서 직접 치는 커밋은 막지 않는다.** 그쪽까지 막으려면
`.git/hooks/pre-commit` 에서 같은 검사 스크립트를 부르면 된다. 두 경로가 같은 스크립트를 공유하므로
기준이 갈라지지 않는다.

## 검사 스크립트 규약

플러그인은 검사 스크립트의 *내용*에 관여하지 않는다. 요구하는 것은 두 가지뿐이다.

- 실행 가능해야 한다 (`chmod +x`)
- 통과하면 exit 0, 실패하면 non-zero

무엇을 검사할지는 프로젝트가 정한다. 참고로 이 플러그인이 태어난 프로젝트의 `scripts/check.sh` 는
lint(문법 + 금지 패턴) → build(단일 파일 제약 + 용량 예산) → test(순수 로직 유닛 테스트) 순으로 돌고,
실패해도 중간에 멈추지 않고 끝까지 돌린 뒤 하나라도 실패했으면 1을 돌려준다.
